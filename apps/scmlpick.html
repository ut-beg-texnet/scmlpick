scmlpick

scmlpick is a SeisComP module that performs real-time seismic phase picking. EQCCT is the default architecture. The same process can run UTrans (utrans_eqcct), PhaseNet, or EQTransformer by setting eqcct.architecture. One process uses one architecture. Several profiles inside that process split stations, messaging groups, and regions. Per-station configuration uses SeisComP bindings. Playback reprocesses stored waveforms.

Seamless integration with SeisComP (official documentation) enables direct publishing of Pick objects to the messaging system, use of station bindings, and interoperability with other SeisComP modules.

Installation

SeisComP System

  • Required: SeisComP

  • Minimum version: Fully compatible with SeisComP releases ≥ 4.0.0

  • Recommended: 6.0.0 or higher for improved stability and performance

Follow the official installation instructions: https://docs.seiscomp.de/ Once installed, verify that SeisComP is properly configured and accessible in your environment.

Operating System

  • Tested on: Linux

  • Validated on: Ubuntu 22.04 LTS

Programming Language

  • Python 3.10, 3.11, or 3.12 on glibc Linux. Python 3.9 and older are not supported. Alpine and other musl systems are outside the TensorFlow wheels used here.

Clone the Repository

git clone https://github.com/ut-beg-texnet/scmlpick.git
cd scmlpick

Deploy the Module

Copy the seiscomp/ directory onto the SeisComP root. Do not copy the repository root.

rsync -a seiscomp/ "$SEISCOMP_ROOT/"

$SEISCOMP_ROOT is usually /opt/seiscomp. The model weights for EQCCT, UTrans, PhaseNet, and EQTransformer are under seiscomp/share/scmlpick/model/ and are included by that copy.

seiscomp/etc/scmlpick.cfg in this repository is one host’s configuration. On another computer, edit the messaging connection, the subscriptions, the model paths, and the profiles before starting the module. Station bindings and region polygons are not stored in the repository.

Python Environment Used by the Service

seiscomp/bin/scmlpick starts /opt/seiscomp/share/scmlpick/pyenv/bin/python when that file exists. Create that environment and install this repository into it. Run the last command from the repository root.

python3 -m venv /opt/seiscomp/share/scmlpick/pyenv
/opt/seiscomp/share/scmlpick/pyenv/bin/python -m pip install --upgrade pip
/opt/seiscomp/share/scmlpick/pyenv/bin/python -m pip install .

That installs the predictor and the libraries declared in the root setup.py: NumPy 1.26, pandas 2.x, SciPy 1.15, ObsPy, Ray 2.59, TensorFlow 2.17.0, and tf-keras 2.17.0. Repeating the last command reinstalls the same package into that environment.

If SeisComP is not installed under /opt/seiscomp, create the environment at $SEISCOMP_ROOT/share/scmlpick/pyenv and point _PY at the top of seiscomp/bin/scmlpick to that interpreter.

python3 setup.py --make-env, run from the repository root, creates .venv inside the repository. That environment is for working on the predictor. The service does not use it.

seiscomp/share/scmlpick/tools/scmlpick-predicctor/setup.py installs the same package when the current directory is already the deployed SeisComP tree (pip install -e . from that directory). A new installation uses the setup.py at the repository root.

Enable and Start

seiscomp update-config scmlpick
seiscomp enable scmlpick
seiscomp start scmlpick

Getting Started

Real-Time Setup

Before starting scmlpick in real time:

  1. Choose one architecture with eqcct.architecture and point eqcct.Pmodel and eqcct.Smodel at the matching weights.

  2. Create one or more profiles in pipelines.profiles. Every profile in this process uses the architecture from step 1.

  3. Set pipelines.profiles.$name.pickTargetGroup and pipelines.profiles.$name.locTargetGroup for each profile.

  4. Create a binding profile with the same name and set profiles.$name.pickEnable (see Bindings).

  5. Assign that binding to the stations in scconfig, or edit the key files.

  6. Start messaging (scmaster or the usual SeisComP workflow).

  7. Launch scmlpick:

    scmlpick -u user --debug

For executing on the command line simply call it with appropriate options, e.g:

seiscomp exec scmlpick -h

Next Steps

  • Add profiles (see Module Profiles) when one architecture must publish to more than one messaging group.

  • Start a second module name when a second architecture must run at the same time. See Picker Architectures.

  • Set the Ray parameters in Tuning for the number of stations on the machine.

  • Use Playback to reprocess miniSEED or a RecordStream.

Picker Architectures

Set eqcct.architecture. The weights under $SEISCOMP_ROOT/share/scmlpick/model/ match the four names below.

eqcct

Compact convolutional transformer. Default. eqcct.Pmodel and eqcct.Smodel are the two ModelPS files test_trainer_024.h5 and test_trainer_021.h5.

utrans_eqcct

EQCCT picking heads on a pretrained U-Trans foundation encoder. The encoder output is concatenated as a fourth input channel. See https://doi.org/10.1038/s41598-026-41454-x. Point Pmodel and Smodel at the Foundation-EQCCT checkpoints test_trainer_P_FoundationEQCCT_026.h5 and test_trainer_S_FoundationEQCCT_025.h5. Plain EQCCT weights do not load here.

phasenet

Official PhaseNet U-Net (Zhu and Beroza, 2019). One checkpoint directory, model/PhaseNet/190703-214543, set as eqcct.Pmodel. eqcct.Smodel is ignored. PhaseNet normalizes each window itself. Its published probability threshold is about 0.3, higher than the EQCCT defaults.

eqtransformer

Official EQTransformer (Mousavi et al., 2020). Point eqcct.Pmodel at model/EQTransformer/EqT_original_model.h5 or at that directory. eqcct.Smodel is ignored. This file was saved with Keras 2 and is opened through the tf-keras package. Published P and S thresholds for the mseed predictor are 0.1. The 1–45 Hz bandpass used in the bindings matches the STEAD preprocessing described for this model.

eqcct.gpuID is the GPU index. Set it to -1 to run on CPU. ray.precision selects bf16 (default) or fp32 for every architecture. The weight files stay float32. bf16 changes the arithmetic.

Module Profiles

Profiles divide one process. They do not select the neural network. eqcct.architecture is shared by every profile in that process.

Use several profiles when the same picker must send picks to different groups, follow different location authors, or apply different region polygons. That is the usual operational layout: one EQCCT process, one profile per network region.

Run a separate process when the architecture must differ. Give that process its own module name: a symbolic link to bin/scmlpick, its own etc/<name>.cfg, and its own etc/key/<name>/ bindings. Each process loads one model and uses its own CPU and memory. Four architectures therefore mean four processes, not four profiles.

Each profile can define its own:

  • pipelines.profiles.$name.pickTargetGroup all picks emitted by this profile are published to that specific messaging group.

  • pipelines.profiles.$name.locTargetGroup this profile subscribes to locations from that messaging group.

  • pipelines.profiles.$name.authorTarget locations carrying this author are checked against the profile’s quality-control parameters.

  • pipelines.profiles.$name.region polygon used to evaluate (filter/validate) locations processed by this profile.

Segment of scmlpick.cfg incuding two profiles:

# List with profiles names.
pipelines.profiles = PROF1, PROF2

# This is the name of the group to send pick messages for specific profile
pipelines.profiles.PROF1.pickTargetGroup = PPROF1

# This is the name of the group to send location messages for specific profile
pipelines.profiles.PROF1.locTargetGroup = LPROF1

# This author should match the origin (location) author for locations to be
# checked against quality control parameters.
pipelines.profiles.PROF1.authorTarget = LOCSATPROF1

# The BNA file defining regions (closed polygons) or tuple with 4 elements.
# Inside this region, the origin evaluation status is TrueOrgEvalStat, and
# outside is FalseOrgEvalStat. If this is set to none, then the origin location
# will not be checked against any polygon.
pipelines.profiles.PROF1.region = @DATADIR@/scmlpick/bna/PROF1.bna

# This is the name of the group to send pick messages for specific profile
pipelines.profiles.PROF2.pickTargetGroup = PPROF2

# This is the name of the group to send location messages for specific profile
pipelines.profiles.PROF2.locTargetGroup = LPROF2

# This author should match the origin (location) author for locations to be
# checked against quality control parameters.
pipelines.profiles.PROF2.authorTarget = LOCSATPROF2

# The BNA file defining regions (closed polygons) or tuple with 4 elements.
# Inside this region, the origin evaluation status is TrueOrgEvalStat, and
# outside is FalseOrgEvalStat. If this is set to none, then the origin location
# will not be checked against any polygon.
pipelines.profiles.PROF2.region = @DATADIR@/scmlpick/bna/PROF2.bna

Note

Each module profile must have a corresponding binding profile that associates the profile with specific stations; see Bindings. The module profile name must match the binding profile name.

Bindings

In SeisComP, bindings attach module-specific parameters to stations. scmlpick uses bindings to activate specific stations to be processed by an scmlpick profile.

Where to Configure

  • In scconfig, assign the binding to the stations.

  • Or edit $SEISCOMP_ROOT/etc/key/<module>/station_NET_STA. <module> is scmlpick, or the name of the symbolic link when more than one architecture is running. seiscomp update-config writes the corresponding files under etc/bindings.

Each binding enables picking for the stations bound to it:

  • profiles.$name.pickEnable Boolean flag to enable picking in this binding.

You can also set a station-specific filter. This filter is applied at the beginning of the processing chain, before the ML algorithm runs:

  • profiles.$name.filter Parameter following the standard SeisComP filter grammar (reference).

Playback

scmlpick supports playback for offline (non–real-time) processing. This mode is useful for validation, benchmarking, parameter tuning, and research.

Data sources

Playback can run against:

  • Pre-downloaded miniSEED files fastest and fully repeatable.

  • Historical data via the configured SeisComP RecordStream (e.g., FDSN/CAPS/SeedLink).

Note

Querying large time windows from a RecordStream can be slow and will re-fetch data on every run. Prefer RecordStream playback for short time intervals or one-off executions. For repeated experiments, use local miniSEED files.

Requirements

Playback uses the same configuration as real-time mode:

  • A module profile (see Module Profiles).

  • Bindings whose profile name matches the module profile (see Bindings).

  • Stations assigned to that binding profile.

  • A valid data source: miniSEED files available locally or a correctly configured RecordStream endpoint.

Note

Keep eqcct.windowLength/eqcct.timeShift and other configuration parameters (see Tuning) consistent with your real-time setup if you want comparable latency and behavior between modes.

Command-line options

Use the following options to run scmlpick in playback mode.

Input source (choose one)

  • --recordstream Read historical data directly from a SeisComP RecordStream (e.g., FDSN/CAPS/SeedLink).

  • --mseed-files <PATH> Read from one or more local miniSEED files, or a directory containing them.

Playback window & profile

  • --profile <NAME> Select the module profile to use. The profile name must match an existing module profile and its corresponding binding profile.

  • --start "YYYY-MM-DD HH:MM:SS"

  • --end   "YYYY-MM-DD HH:MM:SS" Time window for playback, applied to the chosen input source.

Output

  • --output-file <FILE> Write picks to this XML file. The file is replaced as results arrive and holds every pick from the run.

  • --database Send results directly to the SeisComP database.

Ray parallelism (optional)

  • --cpu-number <N> Overrides ray.numCPUs for this run. In model-actor mode that is the number of processes that load the picker. If omitted, the value from the module configuration is used.

  • --max-tasks <N> Maximum number of concurrent tasks sent to the predictor. If omitted, the configured default is used.

Running Playback

Using local miniSEED:

scmlpick \
  --playback \
  --profile playback \
  --mseed-files /data/mseed/2025-08-01/ \
  --start "2025-08-01 00:00:00" \
  --end   "2025-08-01 06:00:00" \
  --output-file /tmp/scmlpick_playback.xml \
  -u user \
  --debug

Using RecordStream:

scmlpick \
  --playback \
  --profile playback \
  --recordstream \
  --start "2025-08-01 00:00:00" \
  --end   "2025-08-01 03:00:00" \
  --database \
  -u user \
  --debug

Tuning

ML algorithm configuration

Controls which pre-trained models are used and how strict the decision rules are. Select P/S models appropriate for your seismicity and set probability thresholds that govern when picks are emitted; overlap and batch size affect latency and throughput.

  • eqcct.architecture

  • eqcct.Pmodel

  • eqcct.Smodel

  • eqcct.eqcctPthr

  • eqcct.eqcctSthr

  • eqcct.gpuID

PhaseNet and EQTransformer ignore eqcct.Smodel. Raise the P and S thresholds toward the values published with those models. The EQCCT defaults, 0.001 and 0.002, are much lower.

Data sent for processing

The model scores eqcct.windowLength seconds (default 60). The process also keeps eqcct.filterShift seconds before that window so the filter can warm up. A packet is therefore windowLength + filterShift seconds long.

The next packet starts windowLength - timeShift seconds later. With windowLength = 60, filterShift = 10, and timeShift = 20, each packet is 70 seconds and the step is 40 seconds. The 20 seconds of eqcct.timeShift are the overlap that two consecutive packets both score.

A station is sent when it holds a full packet. If its start is behind the newest complete packet by less than eqcct.traceDelay (default 120 seconds), it is caught up from its own start, one packet per pass. If it is behind by more than traceDelay, that old packet is not sent. The samples stay in memory and the station joins the live packet when it covers it. Samples older than eqcct.timeRemoveTrace (default 600 seconds) are removed.

The package defaults are filterShift = 2.5 and timeShift = 30. An operational configuration commonly sets them to 10 and 20. Keep one pair of values for a running system. Playback should use the same pair when the results are compared with real time.

These parameters control that schedule:

  • eqcct.windowLength

  • eqcct.timeShift

  • eqcct.filterShift

  • eqcct.minStasBulk

  • eqcct.minDelayStasBulk

  • eqcct.firstWait

  • eqcct.secondWait

  • eqcct.maxWait

  • eqcct.startLatency

  • eqcct.timeRemoveTrace

  • eqcct.traceDelay

Ray configuration

ray.numWorkers splits the station list across worker processes. It does not set how many Ray processes exist. The default is 1. Raise it only when one process is holding more stations than it can cut and return inside one step. ray.numCPUs is the number of model processes started in modelactor mode. Each one loads the picker once. It is not the same setting as ray.numWorkers.

ray.execution is modelactor by default. Each Ray process loads the picker once and reuses it for every station it receives. task loads the picker inside a Ray task for every station. In that mode ray.maxCalls exits the worker after this many finished stations so its memory is returned. The station in progress is not interrupted. modelactor ignores maxCalls.

ray.precision is bf16 or fp32.

  • ray.numWorkers

  • ray.numCPUs

  • ray.maxTasksQueue

  • ray.execution

  • ray.precision

  • ray.maxCalls

Locations quality control

Applies simple, rule-based checks to location results. Uncertainty and geometry thresholds determine whether an origin is assigned the “true” or “false” evaluation status; both statuses are configurable to match your operational workflow.

  • qcheck.latUncTHR

  • qcheck.lonUncTHR

  • qcheck.depthUncTHR

  • qcheck.depthTHR

  • qcheck.azGapTHR

  • qcheck.TrueOrgEvalStat

  • qcheck.FalseOrgEvalStat

whiteChanns

Type: list:string

Define the list of channles types that are allowed to process. Example: HH, CH

eqcct.architecture

Type: string

Picker architecture to use. All options return P/S probability curves on 60 s, 3-component windows. "eqcct": plain EQCCT compact convolutional transformer. "utrans_eqcct": EQCCT picking heads fed by a pretrained U-Trans self-supervised foundation encoder (latent features concatenated as a 4th input channel). See https://doi.org/10.1038/s41598-026-41454-x. When set to "utrans_eqcct", Pmodel/Smodel below must point to Foundation-EQCCT checkpoints, not plain EQCCT weights. "phasenet": official PhaseNet U-Net (Zhu and Beroza, 2019). Pmodel must point at the official 190703-214543 checkpoint directory. Smodel is ignored. Use probability thresholds around 0.3. "eqtransformer": official EQTransformer (Mousavi et al., 2020). Pmodel must point at EqT_original_model.h5 or its directory. Smodel is ignored. Requires the tf-keras package. Published P/S thresholds for the mseed predictor are 0.1. Default is eqcct.

eqcct.Pmodel

Type: string

Model to detect P phases. Must match the architecture selected in "architecture": a plain EQCCT checkpoint for "eqcct", a fine-tuned Foundation-EQCCT checkpoint (U-Trans encoder + picking head, combined in one file) for "utrans_eqcct", the official PhaseNet checkpoint directory for "phasenet", or EqT_original_model.h5 for "eqtransformer".

eqcct.Smodel

Type: string

Model to detect S phases. Same architecture-dependent requirement as Pmodel above. Ignored when architecture is "phasenet" or "eqtransformer".

eqcct.windowLength

Type: int

Define the data window length in seconds to send to eqcct. Default is 60.

eqcct.filterShift

Type: double

Define the time shift to initialize the filter. This data will not be processed, so timeShift must be greater than this. (in seconds) Default is 2.5.

eqcct.probThreshold

Type: double

Minimum probability to reach to send a new pick. Default is 0.001.

eqcct.timeShift

Type: int

Define the time in seconds to overlap with the previous window. Default is 30.

eqcct.minStasBulk

Type: int

Minimum number of stations with windowLength data available to send to EQCCT after firstWait. This number should be less than the total stations. At least this number of real-time stations must be available to produce picks. Default is 5.

eqcct.minDelayStasBulk

Type: int

Minimum number of delayed stations with windowLength data available to send to EQCCT after firstWait. This number should be less than the total stations. Default is 5.

eqcct.firstWait

Type: int

Minimum delay between now and the end time of the last minute saved in memory to compute all data available. First computation. Default is 5.

eqcct.secondWait

Type: int

Minimum time to wait after first computation to proceed with Second computation. Default is 3.

eqcct.maxWait

Type: int

Maximum time to wait after first computation to proceed with second computation. Default is 10.

eqcct.startLatency

Type: int

Define time in seconds to wait before sending the first data packet to eqcct. Default is 60.

eqcct.timeRemoveTrace

Type: int

Maximum time in seconds to wait before remove traces from the processing stream. Default is 600.

eqcct.traceDelay

Type: int

A station this many seconds behind the newest complete window is not sent as its own old window. Its samples stay in memory and it is picked on the live window once that window is covered. A shorter gap is still sent from the station’s own start. Default is 120.

eqcct.eqcctPthr

Type: double

Minimum probability to reach to send a new P pick. Default is 0.001.

eqcct.eqcctSthr

Type: double

Minimum probability to reach to send a new S pick. Default is 0.002.

eqcct.eqcctOverlap

Type: int

If set the detection and picking are performed in overlapping windows. Default is 0.

eqcct.eqcctBatchSize

Type: int

Batch size. This wont affect the speed much but can affect the performance. A value beteen 200 to 1000 is recommended. Default is 1.

eqcct.gpuID

Type: int

GPU index passed to the picker. Set to -1 to run on CPU. Default is 0.

eqcct.gpuLimit

Type: int

Set the maximum percentage of memory usage for the GPU. Default is 1.

pipelines.profiles

Type: list:String

Profile names must match the profiles in the bindings configuration.

pipelines.Standard

Type: boolean

If enabled, the module sends picks to the messaging system as soon as the module produces them. In the default setup, 1-minute windows are processed every 30 seconds. Default is true.

pipelines.Simulation

Type: boolean

If enabled, the module sends picks simulating the true arrival time but includes a delay corresponding to the first processed window. Default is false.

pipelines.Bulk

Type: boolean

If enabled, the module stores picks and sends them to the messaging system periodically, at a configurable time interval. Default is false.

pipelines.bulkInverval

Type: int

Inverval in seconds used when bulk pick delivery strategy is enabled Default is 1800.

Note

pipelines.profiles.* Profiles including specific configurations.

pipelines.profiles = a,b
pipelines.profiles.a.value1 = ...
pipelines.profiles.b.value1 = ...
# c is not active because it has not been added

pipelines.profiles.c.value1 = ...
pipelines.profiles.$name.pickTargetGroup

Type: String

This is the name of the group to send pick messages for specific profile when standard pick delivery strategy is enabled Default is PICK.

pipelines.profiles.$name.pickSimulTargetGroup

Type: String

This is the name of the group to which pick messages will be sent for a specific profile when simulation pick delivery strategy is enabled Default is PICK.

pipelines.profiles.$name.pickBulkTargetGroup

Type: String

This is the name of the group to which pick messages will be sent for a specific profile when bulk pick delivery strategy is enabled. Default is PICK.

pipelines.profiles.$name.locTargetGroup

Type: String

This is the name of the group to send location messages for specific profile Default is LOCATION.

pipelines.profiles.$name.authorTarget

Type: String

This author should match the origin (location) author for locations to be checked against quality control parameters. Default is SCMLPICK.

pipelines.profiles.$name.region

Type: path

The BNA file defining regions (closed polygons) or tuple with 4 elements. Inside this region, the origin evaluation status is TrueOrgEvalStat, and outside is FalseOrgEvalStat. If this is set to none, then the origin location will not be checked against any polygon. Default is none.

ray.numCPUs

Type: int

Size of the Ray CPU pool. This limits how many Python processes run picker work at once. It is not numWorkers. Default is 5.

ray.maxTasksQueue

Type: int

Maximum number of tasks that are sent to the predictor at the same time. Default is 50.

ray.numWorkers

Type: int

Number of groups to split stations. This partitions the station list. It does not set the number of Ray processes; that is numCPUs. Default is 1.

ray.execution

Type: string

How a station reaches the neural network. Used for eqcct, utrans_eqcct, phasenet and eqtransformer. "modelactor": RAPID Model-Actor. Each process loads the picker once and reuses it. Default. "task": previous behavior. Every station loads the picker inside a Ray task. Pair with maxCalls. Default is modelactor.

ray.precision

Type: string

Compute precision for every picker. "bf16": bfloat16 math, the RAPID precision that was fastest while staying close to float32 picks. Official weights stay float32. Default. "fp32": full float32 math. Default is bf16.

ray.maxCalls

Type: int

Task execution only. A worker process exits after this many finished stations so its RAM returns to the system. The station in progress is not interrupted. Ignored when execution is "modelactor". 300 stations is about 2.5 hours at the current rate. Default is 300.

qcheck.latUncTHR

Type: int

Set the latitude uncertainty threshold. Above this value, the origin evaluation status is FalseOrgEvalStat, and below is TrueOrgEvalStat. Default is 20.

qcheck.lonUncTHR

Type: int

Set the longitude uncertainty threshold. Above this value, the origin evaluation status is FalseOrgEvalStat, and below is TrueOrgEvalStat. Default is 20.

qcheck.depthUncTHR

Type: int

Set the depth uncertainty threshold. Above this value, the origin evaluation status is FalseOrgEvalStat, and below is TrueOrgEvalStat. Default is 20.

qcheck.depthTHR

Type: int

Set the depth threshold. Above this value, the origin evaluation status is FalseOrgEvalStat, and below is TrueOrgEvalStat. Default is 20.

qcheck.azGapTHR

Type: int

Set the azimuthal gap threshold. Above this value, the origin evaluation status is FalseOrgEvalStat, and below is TrueOrgEvalStat. Default is 270.

qcheck.TrueOrgEvalStat

Type: int

Set the origin evaluation status to use when the origin fulfills all quality thresholds. Use integers from 0 to 5. Each integer means following next list: 0=preliminary, 1=confirmed, 2=reviewed, 3=final, 4=rejected, 5=reported. Default is 5.

qcheck.FalseOrgEvalStat

Type: int

Set the origin evaluation status to use when the origin does not fulfill one or more quality thresholds. Use integers from 0 to 5. Each integer means following next list: 0=preliminary, 1=confirmed, 2=reviewed, 3=final, 4=rejected, 5=reported Default is 4.
